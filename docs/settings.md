# Настройки: как это работает

Эта страница — справка для администраторов. Раздел [«Настройки»](app:settings) виден только
администратору.

---

## 1. Как устроены настройки

Настройки задаются на трёх уровнях:

- **Настройки системы** — общие значения по умолчанию: базовые ставки, статусы техопераций
  МойСклад.
- **Карточка отдела** — всё, что у каждого отдела своё: права мастеров, ставки, накладные расходы,
  правила себестоимости, склады, шаблоны цеха. Открывается из списка отделов в Настройках.
- **[Статусы заявок](app:order-states)** — какие статусы заявок МойСклад использует программа и как.

Что наследуется, а что нет:

- **Ставки** отдела наследуют общие: пустое поле в карточке отдела — берётся значение из
  Настроек системы. Поменяли общее — все отделы без своего значения сразу считают по новому.
- **Накладные расходы и правила себестоимости не наследуются.** У каждого отдела свой список;
  у нового отдела он пуст — накладные равны 0, надбавок нет.

## 2. Настройки системы

- **Расчёт зарплаты → Базовая ставка пильщика** — ставка по умолчанию для отделов, где своя не
  задана. Ставка за единицу считается от неё и коэффициента товара (см. [Выработка и
  ставки](pay.md)).
- **Ставки мастера → Базовая ставка** — то же для мастера (₽/м²).
- **МойСклад** — точные имена статусов техопераций в МойСклад: «в работе» (операция открыта)
  и «завершена» (операцию закрыли). По ним программа переводит техоперации приёмки и цеха;
  имя должно совпадать с МойСклад символ в символ.
- **Склады по умолчанию для отделов** — только просмотр, правятся в карточке отдела.
- Надбавки за подкол, торцовку, плитку-маску и мелкую плитку задаются не здесь, а правилами
  себестоимости в карточке отдела (раздел 3). Общих коэффициентов для них больше нет.

Кнопка **«Сохранить»** внизу сохраняет все поля страницы сразу.

## 3. Карточка отдела

### Основное

Название, код, описание, руководитель и переключатель **«Отдел активен»**. Неактивный отдел не
предлагается в формах. **«Удалить отдел навсегда»** появляется, только когда в отделе нет
сотрудников.

### Права на операции

Таблица «раздел × должность»: какие разделы шапки видят **Мастер** и **Помощник мастера** этого
отдела. Галочка — раздел виден.

- Метка **«админ»** — раздел только для администратора, галочку поставить нельзя.
- Метка **«всегда»** — раздел виден этой должности всегда и не отключается (например, свой
  дашборд у мастера).
- «—» — для этой должности раздел не настраивается.
- Работник и разнорабочий видят только свою выработку — это не настраивается.

Работник нескольких отделов видит раздел, если он разрешён хотя бы в одном из его отделов.

### Ставки себестоимости

Ставки пильщика и мастера этого отдела. **Пустое поле — значение наследуется** из Настроек
системы; под полем видно, что действует: «Наследуется: X ₽» или «Своё значение · общее: X ₽».

### Накладные расходы

Произвольный список строк «название — сумма, ₽/м²». Сумма всех строк входит в себестоимость
продукции — в стоимость техоперации МойСклад приёмки и цеха. Строка с пустым названием
сохранится как «Расход №N», пустая сумма — как 0. Нет строк — накладные отдела равны 0.

### Правила себестоимости

Надбавки и штрафы к ставке: подкол, торцовка, плитка-маска, мелкая плитка и любые свои.

- **Правило меняет коэффициент, а не рубли.** Итоговый коэффициент позиции — коэффициент товара
  плюс сумма всех сработавших правил. Поднимете базовую ставку отдела — надбавка пересчитается
  сама. Штраф — отрицательное число.
- Слагаемое задаётся **отдельно для пильщика и для мастера**; пустое поле — на эту роль правило
  не влияет.
- **Когда срабатывает:**
  - **вручную** — в форме приёмки или цеха появляется галочка с названием правила;
  - **автоматически по маске SKU** товара: `*` заменяет один сегмент целиком — `04-07-*`,
    `*-*-30`.
- **Только для партий с SKU** — ручное правило доступно, только если SKU партии подходит под
  маску. Пусто — доступно при любой партии.
- **Область действия** — приёмка и цех, только приёмка или только цех.
- **Ключ** правила уникален в отделе. Ключи `undercut` и `edging` связаны с галочками «подкол» и
  «торцовка» в формах — переименуете, и надбавка перестанет применяться.
- Название, цвет и иконка — как правило выглядит плашкой в документах.
- **Правка и удаление правила действуют только на новые документы.** В уже сохранённых позициях
  применённые правила хранятся снимком — посчитанные зарплаты не меняются.

У нового отдела правил нет. Набор по умолчанию (подкол, торцовка, плитка-маска, мелкая плитка)
создаётся вместе с отделами при первой установке.

### Склады по умолчанию

Подставляются в формы документов отдела (в форме их можно поменять):

| Склад | Где подставляется |
|---|---|
| **Сырья** | Приход — склад поступления; Сырьё — склад-источник партии; Цех — склад сырья. |
| **Продукции** | Цех — склад, куда приходит продукт. |
| **Производства** | Сырьё — склад пильщика; Приём — склад приёмки; Заявки — склад комплектации; Цех — склад упаковщика. |

Склад не задан — берётся склад по умолчанию всей программы.

### Шаблоны цеха

Готовые наборы для формы [цеха](workshops.md): сырьё, тара и продукт. Количества — **норма на 1
единицу готовой продукции**: в форме цеха они умножаются на введённое количество. Нужны хотя бы
одно сырьё и один продукт; тара — по желанию. Шаблон можно **скопировать** в другой отдел.

## 4. Статусы заявок

Справочник повторяет статусы заказов покупателей из МойСклад — имена, цвета и порядок.
Кнопка **«Обновить из МойСклад»** подтягивает изменения. Статус, пропавший из МойСклад, не
удаляется, а помечается **«нет в МойСклад»**; галочки при обновлении не сбрасываются.

| Колонка | Что будет, если отметить |
|---|---|
| **Исп.** | Заявки в этом статусе загружаются в программу. **Сняли галочку — заявки в этом статусе пропадут из программы при следующей синхронизации.** |
| **Произв.** | В этом статусе идёт производство: остаток на складе фиксируется, всё произведённое попадает в колонку «Изготовлено» карточки заявки. |
| **В списке** | Статус показывается в списке заявок, когда фильтр по статусу не выбран. Не отмечен ни один — показываются все используемые. |
| **Вниз** | Заявки в этом статусе стоят в самом конце списка, даже срочные (например, «Собран»). Стрелки очереди двигают их только между собой. На раздачу остатка между заявками не влияет. |
| **Следить** | Программа замечает, что в МойСклад изменили количество или состав позиций: мастер видит плашку «Изменена» и «было → стало». Снимите у статусов, где правки нормальны (проект, отгружен, завершён). |
| **Изм.** | Статус «Изменено» — пауза внутри производства: окно производства не закрывается, а кнопка «Принято» у заявки возвращает её в статус, который был до него. Такой статус может быть только один и всегда используется. Строка «Статуса «Изменено» нет» — такого статуса нет. |

Как эти настройки выглядят для мастера — в [справке по заявкам](orders.md).

Документ — единый источник правил раздела: **меняешь правило — обнови этот файл**. В приложении
он отображается страницей справки `settings` (`App\Services\HelpService`, доступ — операция
`admin-settings`), всё начиная с этого заголовка отрезается.

| 3. Отдел: основное | `DepartmentController` (`store`, `update`, `destroy`) | `Department/DepartmentControllerTest` |

Заметки:

- Колонки статусов описаны ещё в `orders.md` §2 — с точки зрения мастера. Меняешь смысл колонки —
  правь оба файла.
- Общие коэффициенты `UNDERCUT_PENALTY`, `EDGING_COEFF`, `MASK_TILE_COEFF_BONUS` и ставка
  `MASTER_UNDERCUT_RATE` в расчётах не участвуют (их заменили правила отдела) и со страниц

  к удалению.
- Кнопка «?» на всех страницах настроек ведёт сюда: `@include('partials.help-button', ['page' => 'settings'])`.
