# Приход: как это работает

Раздел «Приход» (поступления сырья) оформляет сырьё, пришедшее от поставщика. Поступление
создаёт в МойСклад **Заказ поставщику**, а затем **Приёмку** — только она увеличивает остаток
сырья на складе. Из этого сырья потом формируются [партии](raw-batches.md).

Эта страница — справка для мастеров и помощников мастера.

---

## 1. Два шага: сохранить и создать приёмку

1. **Сохранение поступления** (кнопка «Создать поступление сырья») создаёт в МойСклад только
   документ «Заказ поставщику». Остатки на складе не меняются, партии не создаются.
2. **«Создать приёмку»** создаёт в МойСклад «Приёмку» по этому заказу. После этого остатки
   сырья по позициям поступления перечитываются из МойСклад, и сырьё можно выдавать
   в [партии](raw-batches.md).

Пример: пришло 12,5 м³ гранита. Сохранили поступление — на складе пока ничего не изменилось.
Нажали «Создать приёмку» — на складе сырья стало на 12,5 м³ больше, можно создавать партию.

## 2. Создание поступления

Кнопка **«Поступление сырья»** в списке.

| Поле | Как заполняется |
|---|---|
| **Поставщик** | Обязательно. Поиск по контрагентам из МойСклад. |
| **Склад приёмки** | Обязательно. По умолчанию — склад сырья вашего отдела (см. [Настройки](app:settings)), если он не задан — склад, в названии которого есть «сырь». Архивные склады не предлагаются. |
| **Сырьё** | Хотя бы одна позиция: товар и количество (м³, больше нуля). По умолчанию в выборе только сырьё (артикул начинается с «01-»), галочка «весь каталог» снимает фильтр. Сумма показывается в «Итого». |
| **Номер партии** | Номер поступления. Подставляется автоматически; переключатель «Задать вручную» позволяет ввести свой. |
| **Мастер-приёмщик** | Необязательно. В списке — администраторы, мастера и помощники мастера. По умолчанию — вы. |
| **Примечание** | Необязательно. |

- **Номер** имеет вид `ГГ-НН-ПРОГ-ПП`: год, неделя, «ПРОГ» и порядковый номер. Счётчик
  недельный и общий для всех отделов. Пример: третье поступление на 15-й неделе 2026 года —
  `26-15-ПРОГ-03`.
- **Отдел поступления** — отдел мастера-приёмщика. Если приёмщик не указан, поступление
  останется без отдела и будет видно только администратору.
- **Дату создания** задним числом может поставить только администратор.
- Справа — **«Последние поступления»** ваших отделов; из них можно скопировать поступление
  в форму. Кнопка **«Копировать»** есть и в списке.

## 3. Статусы

| Статус | Что значит |
|---|---|
| **Новый** | Поступление сохранено, Приёмки в МойСклад ещё нет. |
| **Синхронизирована** | Приёмка создана, остатки обновлены. Менять поступление больше нельзя. |
| **Ошибка** | МойСклад не принял Заказ поставщику при сохранении или правке. Текст ошибки — в карточке. |

## 4. Создание приёмки

- В списке — иконка облака у поступлений «Новый», в карточке — кнопка в блоке «МойСклад»:
  **«Создать приёмку»**, после ошибки — **«Повторить синхронизацию»**.
- Успех → статус «Синхронизирована», остатки сырья обновлены.
- Ошибка МойСклад → статус не меняется, текст ошибки показывается в карточке.
- Если что-то мешает, откроется экран **«Подтверждение синхронизации»**:

| Ситуация | Что предлагается |
|---|---|
| Заказ поставщику не создан в МойСклад | «Создать Заказ поставщику + Приёмку» или «Создать только Заказ поставщику». |
| Заказ поставщику удалён из МойСклад | То же самое — воссоздать заказ с приёмкой или только заказ. |
| Приёмка с таким номером уже существует | «Создать Приёмку «номер_01»» — номер поступления в программе тоже станет таким. |

- В любом варианте есть **«Отмена»** — ничего не создаётся.
- После «Создать только Заказ поставщику» программа возвращает в карточку, откуда затем
  создаётся приёмка.

## 5. Номер и совпадение имён в МойСклад

- Документы в МойСклад называются номером поступления.
- Если такое имя уже занято, к номеру добавляется суффикс: `26-15-ПРОГ-03` →
  `26-15-ПРОГ-03_01`, повторно — `_02`. **Номер поступления в программе меняется** на новый.
- При сохранении и при воссоздании заказа суффикс добавляется автоматически, для Приёмки
  программа сначала спрашивает (см. таблицу выше).

## 6. Редактирование и удаление

- **Редактировать** можно только поступления «Новый» и «Ошибка». Изменения сразу
  отправляются в Заказ поставщику в МойСклад; если МойСклад отказал, поступление сохраняется
  со статусом «Ошибка».
- **Удалить** мастер и помощник могут только поступления «Новый» и «Ошибка», администратор —
  любые, в том числе «Синхронизирована».
- При удалении программа сначала удаляет в МойСклад Приёмку (остатки откатываются), затем
  Заказ поставщику. Если МойСклад отказал, поступление в программе **не удаляется**, а текст
  ошибки виден в карточке. Если Приёмку удалить удалось, а заказ — нет, поступление
  возвращается в статус «Новый».
- Партии, уже созданные из этого сырья, удаление поступления не трогает.

## 7. Отделы и видимость

- Список по умолчанию показывает поступления ваших отделов; другие отделы можно выбрать
  в фильтре. Фильтры: отдел, поставщик, даты.
- Поступления без отдела видит только администратор.
- Карточку поступления чужого отдела открыть можно, а менять, удалять и отправлять в
  МойСклад — нельзя.

## Для разработчиков

Документ — единый источник правил модуля: **меняешь правило — обнови этот файл**. В приложении
он отображается страницей справки `supplier-orders` (`App\Services\HelpService`), всё начиная
с этого заголовка отрезается.

| Раздел | Код | Тесты (`tests/Feature/SupplierOrder/`) |
|---|---|---|
| 1–2. Создание | `SupplierOrderController::create`, `store`, `nextOrderNumber`; `SupplierOrderService::create`, `nextOrderNumber`, `getFormOptions`, `getRecentOrders`; `StoreSupplierOrderRequest` | `SupplierOrderTest` |
| 3. Статусы | `SupplierOrder::statusLabel`, `isNew` | `SupplierOrderTest` |
| 4. Приёмка | `SupplierOrderController::sync`, `syncConfirm`, `forceSync`; `Moysklad\SupplierOrderSyncService::initiateSync`, `forceSync` | `SupplierOrderTest`, `SupplierOrderSyncActionsTest` |
| 5. Имена | `SupplierOrderSyncService::syncOrderToMoysklad`, `createPurchaseOrderWithFallback`; `DocumentNaming::weeklyName`, `nextSuffix` | `SupplierOrderTest`, `SupplierOrderSyncActionsTest` |
| 6. Правка / удаление | `SupplierOrderController::update`, `destroy`; `SupplierOrderSyncService::updateOrderInMoysklad`, `deleteOrderWithSupply`; `UpdateSupplierOrderRequest` | `SupplierOrderTest` |
| 7. Видимость | `SupplierOrderService::getIndexData`; `SupplierOrderPolicy` → `DepartmentAccess` | `SupplierOrderDepartmentAccessTest`, `Access/RecordDepartmentAccessTest` |

Заметки:

- Документ МойСклад «Приёмка» — `MoySkladSupplyService`, его id — `supply_moysklad_id`;
  «Заказ поставщику» — `MoySkladPurchaseOrderService`, id — `moysklad_id`.
- `isNew()` истинно для `new` **и** `error`: обе означают, что Приёмки ещё нет.
- Вопрос экрана подтверждения живёт в сессии `sync_confirm_{id}`; без него `sync-confirm`
  редиректит на список.
- В форме нет поля отдела: `department_id` вычисляется из `receiver_id`.
